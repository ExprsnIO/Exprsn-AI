Cloudflare edge and hosting

Cloudflare does two jobs. As a front door it puts DNS, edge TLS, a Tunnel, WAF rules and optionally Access in front of any deployment, including an on-premises one. As a host it runs the app tier on Cloudflare Containers, while PostgreSQL, Redis and the GPUs stay on AWS, Azure, DigitalOcean or on premises. It is never a full platform host.

Hybrid hosting on Cloudflare Containers

nw-edge-cf runs the app image on Cloudflare Containers with the console's static assets on Workers static assets. Everything stateful lives on another provider: Hyperdrive pools connections to PostgreSQL, Redis comes from a managed cache, objects go to R2 and the gateway reaches GPU pools over mTLS.

Containers and Hyperdrive · B-10905
The entry Worker routes /api, /v1 and /socket.io to the containers and serves the console from static assets. Hyperdrive connects to PostgreSQL on any provider, or on premises through a Tunnel. Migrations run as a one-off container before traffic switches.
Redis is required
BullMQ, the Socket.io adapter and the cross-instance bus need Redis. Cloudflare has no managed Redis and Workers KV is not a substitute, so the wizard requires a cache on another provider. How Containers reach a private cache is an open decision.
R2 · B-10906
R2 is an object store target through the existing S3 adapter (BLOB_STORE=s3, region auto): files, backups, training artefacts and export bundles. The EU jurisdiction keeps confidential objects in the EU.
